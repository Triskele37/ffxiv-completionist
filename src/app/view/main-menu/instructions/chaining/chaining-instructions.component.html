Overview
"Chaining" is the term used for when the app auto-marks a related task to the one just marked
  • Tasks are chained backwards if the marked task could not have been completed without the previous
  • Tasks are chained together if it is not possible to have one without the other
  • Tasks can chain to exclude another task if they are mutually exclusive
  • Tasks can be chained if each required task is completed
  • Numeric tasks can be chained in the same way normal tasks can
Chaining is disabled by default, this can be changed in the settings page
Specifics
Items that must be used after acquiring them from another task are not chained
Tasks that require "X" amount of some thing may not be chained if:
  • X is something other than 1, all, or a contiguous range
  • That thing is not a numeric completion task
Interface
Any page with a table will have the chain overlay available
The overlay button will pulse if the most recently marked task chained to other tasks
Affected groups can be navigated to using the dropdown
An undo is available for the most recently chained events

NOTE: Undo is not available for chains from custom tasks or setting starting class
Settings
Enable/Disable: Allows you to turn chaining on or off completely
History Limit: The amount of chained events to keep in memory to undo
Min Threshold: Sets the number of chained tasks allowed before collapsing groups within the chain overlay

NOTE: Setting the history limit too high and keeping the app open for days may cause memory issues
